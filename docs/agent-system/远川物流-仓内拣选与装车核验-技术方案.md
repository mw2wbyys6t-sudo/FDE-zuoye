# 远川物流 · 仓内拣选与装车核验｜最小试点技术方案

版本：v0.1（待评审）｜场景：远川物流一次具体事件｜依据：六角色访谈 f00–f55

> 一句话：**判定用确定性规则，解释才用模型**。在装车前把「这单状态变了」和「这个规格可能拿错」以可核对的原记录形式亮给现场，只提示、不阻断、不写业务库。

---

## 1. 目标与不做什么

**要交付的业务结果**
1. 装车前拦得住两类已知错例：相似包装 SKU 规格错拿、取消单仍被拣出装车。
2. 复核漏扫趋近于零（可判定、可审计）。
3. 重复复核工时可控压缩，且收益扣除维护与人工复核成本后仍为正（f03）。

**明确不做（边界，须写进方案评审）**
- 不自动操作叉车、不做盘盈盘亏自动处理（f05/f52）。
- 不回写 WMS 业务状态、不改货位与库存（f32）。
- 不做「阻断型」拦截：是否阻断属业务规则，须顾明岚与傅景书面批准（f34）。
- 不做跨系统主数据改造，只做只读聚合与主编号归一。
- 不在本期做拣选差异放行、装车异常关闭的自动审批（审批矩阵未核实，f41）。

**当前证据下的三个前提**（不成立则方案失效）
- 错发确实有相当比例发生在拣选与装车两段（**未分解，先回溯**）。
- 取消事件可从 OMS 取得，延迟可测（已知均值 12 分钟，P50/P95 未测，f31）。
- 波次、扫码事件、货位表、SKU 图片可按业务编号关联（**可关联比例未测**，f33）。

**关键取舍**
- 判定不用大模型。错发拦截要求「同一输入必得同一输出、每条结论可回溯到字段」，规则引擎才满足；模型只在解释层把规则结果写成一句现场能懂的话，输入受限于结构化字段，不自由生成。
- 不做实时全量同步。取消事件本身有 12 分钟延迟，追求秒级同步没有意义；改为「事件增量 + 状态每天两次全量」，并把数据截止时间显式展示。
- 不做阻断。提示是提示，处置权留在人手上，这样误判的代价从「停线」降为「多点一次」。

## 3. 规则设计（核心）

| 编号 | 触发条件（确定性） | 输出 | 兜底 |
|---|---|---|---|
| R1 规格差异 | 同货位或相邻货位存在 `base_sku` 相同、`spec` 不同的在库 SKU；且当前拣选行的 SKU 命中相似包装组 | 规格差异卡：并排图片 + 规格关键字段 diff（容量/口味/包装数）+「请核对实物标签」 | 相似度仅按结构化字段计算，字段缺失即不出卡；出卡后 3 秒内可标「已核对」 |
| R2 取消状态 | 该业务编号存在 `cancel_event`，且 `cancel_ts > 该单最后一次装箱/扫码前的可见状态时间` | 「该单已取消，暂停建议，交波次计划员核对」+ 取消时刻 + 数据截至时间 | 12 分钟窗口内事件可能未到达：显示「数据截至 HH:mm，可能滞后 12 分钟」，不承诺实时 |
| R3 说明随单 | 拣选行存在非正式说明（便签/群消息登记） | 把说明结构化进单据字段（业务编号、版本、处理状态、未解决事项、接手人），随单流转 | 无说明则不出卡；说明超过一个更新周期标「待刷新」（f34） |
| R4 转人工 | 命中 R1/R2 但资料缺依据、两版本冲突、关键系统不可用、或用户点「我不确定」 | 生成转人工记录：触发原因 + 接手人 + 确认时间 | 三要素缺一不予关闭；关闭动作留痕（f44） |

**规则版本管理**：规则集带生效日期与适用范围；两版冲突时附两版给傅景裁定，系统不自行合并、不选宽松条款（f24）。

**提示卡的固定三段式**（手持终端一屏可读）：
1. 结论：一句话（例：「同货位 3 号位有同系列不同规格，请核对实物」）。
2. 依据：原记录编号 + 字段 + 数据截至时间（f15 要求可显示原记录与待确认字段）。
3. 下一步：可点选的动作（已核对 / 交计划员 / 上报异常），且**不允许覆盖原记录**。

## 4. 数据与接口

### 4.1 数据清单与实时性要求

| 数据 | 来源 | 字段要点 | 实时性 | 缺失时的降级 |
|---|---|---|---|---|
| 波次与拣选行 | WMS | 业务编号、波次号、SKU、货位、状态、版本 | 每天两次全量 + 增量 | 用带时间戳只读快照，界面标「暂未更新」（f35） |
| 扫码事件 | 手持终端 | 业务编号、扫码时刻、节点（拣选/复核/装车）、操作岗 | 准实时（提示依赖） | 本地队列暂存，重连按业务编号去重补齐 |
| 取消事件 | OMS | 业务编号、取消时刻、取消原因 | 准实时（已知延迟 12 分钟） | 显示数据截止时间，不承诺实时 |
| SKU 与货位 | 主数据 | SKU、品名、规格字段、图片、货位、相邻关系 | 每天两次 | 用上一版并标版本号 |
| 交接与退回记录 | WMS / 交接单 | 业务编号、版本、状态、未解决事项、接手人、确认痕迹 | 按事件 | 无记录则不推断交接完成（仅发消息不算完成，f23） |

### 4.2 核心数据模型（简化）

```
pick_line(biz_id PK, wave_id, sku, location, status, ver, updated_at)
scan_event(event_id PK, biz_id, node, ts, operator_role, terminal_id)
cancel_event(biz_id PK, cancel_ts, reason, received_ts)      -- received_ts 用于算延迟
sku_spec(sku PK, base_sku, spec_json, image_url, pack_similarity_group)
location_map(location PK, zone_id, neighbor_locations[])      -- 相邻货位
hint_record(hint_id PK, biz_id, rule_id, rule_ver, evidence_refs[],
            shown_at, action, operator_role, data_asof, signer)
handoff_record(biz_id, ver, status, open_items, next_owner, ack_at)
fallback_record(fallback_id PK, biz_id, trigger_reason, owner, confirmed_at, closed_at)
```

### 4.3 接口约定

- 全部只读，接口权限按岗位授权，禁止共用账号（f41）。
- 每个响应带 `data_asof`、`source_version`；前端必须展示，不允许隐藏。
- 幂等键：`biz_id + rule_id + rule_ver`，同一业务同一规则只提醒一次，除非状态变化（f35）。
- 超时与失败：3 秒超时即降级返回快照 + 「暂未更新」，不阻塞作业。

## 5. 交互设计要点

- **拣选终端**：提示卡不遮挡扫码框；一屏三行内可读完；「已核对」一键，不新增填表。
- **无法离场补录**：草稿本地暂存，显示「最后同步 HH:mm」，未同步条目明确标识（f13）。
- **装车核验页**：取消单提示置顶，显示取消时刻与数据截至时间；错配提示只列差异字段，不做整单复述。
- **计划员处置台**：待核对队列按超时排序，超时升级仓储经理；跨岗转交必须填下一责任人，否则不允许关闭（f25）。
- **审计视图**：按业务编号重建「订单归集 → 波次分配 → 拣选 → 复核 → 集货 → 装车扫码」中的这次处理，只记必要字段，不记口令与不必要个人信息（f45）；评价记录默认留存 90 天，期满由安全主管复核删除或归档，删除动作本身留痕（f43）。

## 7. 验证路径（先回放，后影子，再并行）

1. **离线回放**：取一个仓区近三个月已知错例，跑 R1/R2，输出命中率、误判率、漏拦清单。命中率不达标就不进入下一步。
2. **影子模式**：真实作业中照常运行，提示只记录不展示，校准召回与噪声。
3. **小范围并行**：单仓区、相邻货位相似包装 SKU 范围，原流程不撤、随时可退回（f05）。
4. **验收**：错发率下降 + 复核漏扫为零，且高位叉车/危险品/冷链规程未放宽；触及停止条件即暂停并由负责人复盘（f42/f40）。

**回放评估必须固定的口径**：错发率分子（按单/按行）与分母（仓内出库单 / 站点正确收货单）双列并行、取消单单列、以业务编号唯一计数、周期为试点前一个月回算 + 试点期同口径（f50/f53）；漏扫判定规则由秦芮出数、傅景确认。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 12 分钟同步延迟 | 窗口内取消单拦不住，价值被高估 | 显式展示数据截止时间；把「窗口内存量率」列为验收指标；阻断型另走审批 |
| 主编号不一致、编码不统一 | 提示关联不到原记录，误判无法归因 | 先做对齐试跑，可关联比例达标才上线；歧义进人工修复队列 |
| 误判导致一线停线 | 一线抵触，节拍受损 | 回放先测误判；提示可一键忽略；不阻断、不覆盖原记录 |
| 数据只读但涉及岗位行为 | 权限与合规争议 | 按岗位授权、禁止共用账号；审计只记必要字段 |
| 审批矩阵未定 | 兜底无人负责，上线阻断 | G2 前成文；三要素缺失不予关闭 |
| 口径未冻结 | 验收各说各话 | 口径签字 + 回算可复现后才进试点 |
