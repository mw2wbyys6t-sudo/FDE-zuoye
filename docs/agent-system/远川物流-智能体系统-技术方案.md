## 0. 决策摘要（ADR）

**决策问题**：在离线/弱网、只读数据、22 万首期、单仓区试点的约束下，用什么形态的智能体系统，能把「访谈证据 → 口径 → 方案 → 验收」这条 FDE 链路做成可验证、可回放、可迁移的系统？

**决策**：**Harness 优先的模块化单体 + 多智能体流水线**。

1. 先写 harness（契约、执行器、证据闸门、trace/replay、评估集），再写 agent。Agent 只是 harness 里的可替换步骤，换模型不改业务代码。
2. 判定不用 LLM：错发拦截、口径判定、边界校验全部是确定性代码；LLM 只做抽取、归类、解释、草稿。
3. 单体优先，不为"多 agent"引入微服务。Agent 间用进程内消息与状态机边，跨进程只在推理服务处必然发生。
4. 本地推理通过 OpenAI 兼容网关抽象；开发用 Ollama，压测用 vLLM，切换只改 `config.yaml`。
5. 记忆用 Mem0（自托管）+ 分层写入策略；知识库按四维建模，检索先元数据过滤再向量召回再 rerank。

**已拒绝的替代方案**

| 方案 | 拒绝理由 |
|---|---|
| 直接大模型端到端（一个 prompt 出结论） | 结论无法回溯到字段，验收时无法解释；同输入不同输出，不能用于拦截类业务 |
| 微服务化多 agent（每 agent 一个服务） | 单仓区试点规模不需要独立扩缩容，运维成本与故障面被放大；违反"只为具名收益付分布式成本" |
| 云端大模型 API | 访谈含岗位与客户信息，出境与留存不可控；现场弱网，P95 不可控 |
| 纯 RAG 问答 | 无状态机、无人工闸门，无法承载审批与停止条件；只能答，不能交付 |

**可逆性**：模型（低，改配置）、向量库（低，可切 pgvector）、记忆（中，Repository 接口 + 适配器）、编排（中，LangGraph 可降级为自研状态机）。**重新评估触发条件**：本地模型 JSON 合法率 < 95%，或评估集连续两轮不过。

## 1. 目标与非目标

**目标**
- G1 离线可运行：断网时证据提取与口径校验仍可跑（模型不可用时降级为规则+模板）。
- G2 可验证：每条结论必须带 `fact_id`，无证据必须拒答。
- G3 可回放：任一次运行可按 trace 完整复现，用于验收与归因。
- G4 可迁移：换行业/换仓只需换知识库与术语表，不改代码。
- G5 可交付：输出直接对齐业务口径（分子、分母、周期、出数人）。

**非目标**
- 不做实时阻断、不写业务库、不自动操作叉车/盘盈盘亏。
- 不做自动审批：拣选差异放行、装车异常关闭、规则版本冲突必须人工签核。
- 不做通用聊天助手；所有能力围绕 FDE 交付链。

**约束**：只读接口（f32）、仅授权岗位可见（f41）、评价记录留存 90 天（f43）、审计不记口令与不必要个人信息（f45）、数据可能滞后 12 分钟（f31）且状态每日两次更新（f34）。

## 2. Harness 工程（本项目的第一等公民）

### 2.1 五层定义

| 层 | 职责 | 实现位置 | 失败时的行为 |
|---|---|---|---|
| H1 契约层 | 所有 agent 输入输出用 Pydantic 模型 + JSON Schema 强约束；非法即拒 | `app/harness/schema.py` | 抛 `E_SCHEMA`，带字段路径与修复提示 |
| H2 执行层 | 统一 Runner：prompt 版本、模型版本、`temperature=0`、seed、超时、token 预算、重试、降级 | `app/harness/runner.py` | 重试 2 次后降级到规则/模板，标 `degraded=true` |
| H3 闸门层 | 证据闸门（claim→fact_id）、边界闸门（禁写/禁自动审批）、权限闸门（角色可见性）、脱敏 | `app/harness/guards.py` | 拦截并转人工，写 `fallback_record` |
| H4 追踪层 | 全链路 trace：输入哈希、prompt 版本、模型版本、原始输出、校验结果、耗时 | `app/harness/trace.py` | trace 写失败不阻塞业务，落本地 JSONL 兜底 |
| H5 评估层 | 黄金集（含负例）、确定性断言 + rubric、CI 门禁、回放 | `evals/` + `scripts/eval_run.py` | 指标不达标即阻断合并 |

### 2.2 适配函数（可测的架构不变量）

| 编号 | 被测属性 | 指标 | 阈值 | 来源 | 频次 | 失败响应 | 本地检查 |
|---|---|---|---|---|---|---|---|
| FF1 | 证据可追溯 | 带 `fact_id` 的结论占比 | 100% | trace | 每次运行 | 拒绝发布 | `scripts/verify_p3.py` |
| FF2 | 无证据拒答 | 负例集正确拒答率 | ≥ 95% | `evals/cases/no_evidence.yaml` | 每次提交 | 阻断合并 | `pytest -q evals/test_guards.py` |
| FF3 | 输出结构稳定 | schema 合法率 | 100% | runner 日志 | 每次运行 | 重试→降级 | `pytest tests/test_schema.py` |
| FF4 | 边界零越权 | 写操作/自动审批出现次数 | 0 | guards 日志 | 每次运行 | 落闸并告警 | `scripts/verify_p4.py` |
| FF5 | 响应预算 | 单任务 P95 | ≤ 8s（14B/单卡） | trace | 每日 | 降级到 7B 或规则 | `scripts/bench_p95.py` |
| FF6 | 可回放 | 相同 trace 重放一致率 | 100%（结构）/ ≥90%（语义） | replay | 每次发布 | 阻断发布 | `scripts/replay_check.py` |
| FF7 | 依赖方向 | `agents → harness → infra` 单向 | 违规 0 处 | import 分析 | 每次提交 | 阻断合并 | `scripts/check_imports.py` |

### 2.3 Agent 与 harness 的关系

```
agent = prompt(版本化) + schema(强约束) + tools(只读) + guards(闸门)
        ↓ 全部经 runner 执行
      trace → 评估集 → 回放
```

任何 agent 不得直接调模型 SDK，只能 `runner.run(spec)`；任何 agent 不得直接写库，只能经 `repository` 接口。

```

│ 接口层 FastAPI：统一 envelope {"ok","data","error"}            │

└───────────────────────────┬────────────────────────────────────┘
```

### 3.1 智能体职责与边界

| Agent | 输入 | 输出（强 schema） | 不做 |
|---|---|---|---|
| A1 证据抽取 | 访谈原文、现状信息请求表 | `Fact[]`：id、来源文件、版本、时间窗、角色、原话摘要、等级（事实/估计/推算/待定） | 不合并矛盾、不补推缺失值 |
| A2 冲突检测 | `Fact[]` | `Conflict[]`：同一指标的不同值、完成口径分歧、范围分歧 | 不裁定谁对，只标注并给核对问题 |
| A3 口径基线 | `Fact[]` + `Conflict[]` | `Indicator[]`：分子、分母、周期、来源、责任人、现状值、等级、缺口 | 不把估计当基线，缺项写 `TBD` |
| A4 方案生成 | `Indicator[]` + 规则库 | `Design`：最小试点、接口边界、规则草案、验收与停止条件 | 不产出写操作、不指定未核实审批人 |
| A5 独立核验 | 上游全部产物（只读，独立上下文） | `Verdict[]`：pass/fail/needs_human + 依据 + 缺失项 | 不修改产物，只判定 |
| HumanGate | `Verdict` 中 `needs_human` 项 | 签核记录（谁、何时、依据） | 超时自动通过（禁止） |

**上下文隔离原则**：A5 不复用 A1–A4 的对话历史，只接收结构化产物与事实台账，避免"自己批自己"。

### 3.2 有界上下文（Bounded Contexts）

| 上下文 | 责任 | 模型 | 上游 | 下游 | 关系 | 翻译面 |
|---|---|---|---|---|---|---|
| 证据域 | 事实台账与来源 | Fact / EvidenceRef | 访谈材料 | 口径域、方案域 | Customer/Supplier | 原文→Fact 结构 |
| 口径域 | 指标定义与缺口 | Indicator / Gap | 证据域 | 方案域、评估域 | Conformist | 估计值→带等级字段 |
| 规则域 | 红线、审批、版本 | Rule / Approval | 制度文件 | 方案域 | 共享内核 + 防腐层 | 自然语言规则→可执行判定 |
| 方案域 | 试点与技术方案 | Design / Boundary | 口径域、规则域 | 评估域 | Customer/Supplier | 方案→可测断言 |
| 评估域 | 黄金集、回放、评分 | Case / Trace | 全部 | — | Separate ways | 产物→评分用例 |

### 3.3 交互风格决策

- **同步**：单人、单任务的 FDE 会话（请求-响应），P95 ≤ 8s 可接受。
- **批处理**：知识库入库、历史回放、评估集跑批，走 CLI/worker，不进同步链路。
- **事件**：不做。当前没有多消费者、无实时性要求；取消事件的 12 分钟延迟使实时推送无业务价值（f31）。
- 结论：**默认同步 + 批处理旁路**，不引入消息队列（Redis 仅在需要限流时启用）。

## 4. 技术栈

| 层 | 选型 | 理由 | 替代 |
|---|---|---|---|
| 语言/框架 | Python 3.11 + FastAPI + Pydantic v2 | 契约优先、类型检查友好、生态成熟 | — |
| 编排 | LangGraph（状态机 + checkpoint） | 可中断/可恢复/可视化，适合有人工闸门的流程 | 自研状态机（更轻，缺生态） |
| 本地推理 | Ollama（开发）/ vLLM（吞吐），OpenAI 兼容 | 换模型不改代码；离线可控 | llama.cpp server |
| 主模型 | Qwen2.5-14B-Instruct（主）/ Qwen2.5-7B（降级） | 中文与结构化输出稳，显存可控 | Llama-3.1-8B |
| 向量 | bge-m3（dense+sparse）+ bge-reranker-v2-m3 | 中文与长文检索稳定，混合检索 | m3e / gte |
| 向量库 | Qdrant | 本地 docker、混合检索原生支持 | pgvector（少一个组件） |
| 结构化库 | PostgreSQL 16 | 事实台账、指标、审计、状态机 checkpoint | SQLite（仅单机 demo） |
| 记忆 | Mem0 自托管（向量 + 可选图） | 分层记忆与写策略可控，可替换适配器 | Letta / 自研 |
| 观测 | OpenTelemetry + JSONL trace；可选 Langfuse | 离线可用，先保证可回放 | 仅 JSONL |
| 打包 | Docker Compose + uv | 离线 wheel 打包，一键起 | poetry |
| 质量 | ruff + mypy + pytest + 自定义 lint | 统一 envelope/注释/docstring 可机器检查 | — |

**显存与吞吐预算（ASSUMED，需实测）**：14B INT8 约 16–20GB，单卡 24GB 可跑，`max_model_len=8k`；7B 量化作为降级。P95 目标 8s 基于 14B/单卡/单请求。

## 5. 记忆框架设计（Mem0 + 分层策略）

**四类记忆**

| 类型 | 内容 | 写入时机 | 生命周期 |
|---|---|---|---|
| working | 当前任务上下文、已用事实 id | 每轮 | 任务结束释放 |
| episodic | 任务轨迹摘要（做了什么、结论、失败点） | 任务结束 | 90 天，与审计留存一致（f43） |
| semantic | 已确认事实、口径定义、规则条款 | **仅核验通过后** | 随版本，带 `valid_from` |
| procedural | 流程模板（访谈六问、口径采集七步） | 人工发布 | 版本化 |

**写策略（关键）**
1. 只有 `Verifier` 判 pass 且带 `fact_id` 的内容可写 semantic；未核验内容只进 working。
2. 冲突不自动合并：写 `Conflict` 记录并保留两值，等人工裁定；规则版本冲突附两版（f24）。
3. 每条记忆带 `source_version`、`valid_from`、`confidence(事实/估计/推算/待定)`、`visible_roles`。
4. 检索时先按 `visible_roles` 与版本过滤，再做向量召回，避免"越权召回"。

**环境自适应**：首次运行生成 `env_profile`（行业术语表、角色表、口径字典、可用工具集），存入 procedural 记忆；换仓/换行业只换 profile 与知识库，不改代码。

**降级**：Mem0 不可用时降级为本地 SQLite + 关键词检索，功能受限但流程不断（标 `degraded=true`）。

## 6. 多维知识库

**四维 × 三轴**

| 维度 | 内容 | 举例 |
|---|---|---|
| D1 事实 | 访谈事实台账 | f11 取消单事件、f31 12 分钟延迟 |
| D2 规则 | 红线、审批、版本 | f40 现场规程、f41 账号、f44 转人工三要素 |
| D3 指标 | 口径定义 | 错发率分子分母、漏扫定义、出数人 |
| D4 案例 | 错例与回放 | 已知错例清单、误判例子、回放结果 |

**三轴元数据**：时间（版本/生效日期）、角色（可见性）、置信（事实/估计/推算/待定）。

**入库流水线**：解析（md/html/json）→ **按事实条目切分而非按段落**（保留 `f` 编号完整性）→ 元数据必填校验 → 去重（业务编号 + 内容哈希）→ 双索引（dense + sparse）→ 抽样校验（人工 5%）。

**检索**：元数据过滤（域/版本/角色）→ 混合召回 top-k → rerank → 证据组装（返回 `fact_id` 与原文片段）→ 闸门（不足则拒答）。

## 7. 接口契约

统一返回：`{"ok": bool, "data": any, "error": {"code": str, "msg": str}}`；分页与 trace 字段放 `data` 内。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/v1/health` | 存活与依赖状态（模型/向量库/数据库） |
| POST | `/v1/tasks` | 建任务（场景、角色、范围） |
| POST | `/v1/tasks/{id}/intake` | 摄入访谈材料 |
| POST | `/v1/tasks/{id}/evidence` | A1 抽取 |
| POST | `/v1/tasks/{id}/conflicts` | A2 检测 |
| POST | `/v1/tasks/{id}/baseline` | A3 口径 |
| POST | `/v1/tasks/{id}/design` | A4 方案 |
| POST | `/v1/tasks/{id}/verify` | A5 核验 |
| POST | `/v1/human-gate/{id}/decide` | 人工签核（仅授权角色） |
| GET | `/v1/tasks/{id}/trace` | 全链路 trace |
| POST | `/v1/kb/ingest` | 知识入库（批） |
| POST | `/v1/memory/search` | 记忆检索（带角色过滤） |
| POST | `/v1/eval/run` | 跑评估集 |

**错误码**：`E_SCHEMA`、`E_NO_EVIDENCE`、`E_BOUNDARY`、`E_PERM`、`E_MODEL_UNAVAILABLE`、`E_TIMEOUT`、`E_HUMAN_REQUIRED`、`E_CONFLICT_UNRESOLVED`。

```yaml
  base_url: ${EMBED_BASE_URL}
```

**规范与检查的对应关系**

| 规范 | 落地方式 | 检查 |
|---|---|---|
| 每个函数中文 docstring（入参/出参/失败行为） | Google 风格中文 docstring | `ruff` D 规则 + 自定义 AST 检查 |
| 安全/权限/人工确认必须有行内注释说明"为什么卡" | `# 原因：...` 紧邻判定行 | `scripts/check_comment_rules.py`（AST 定位函数名白名单） |
| 配置集中 `config.yaml`，禁硬编码密钥/模型地址 | 只允许 `${ENV}` 引用 | `scripts/check_config.py` 扫 `sk-`、`http://` 字面量 |
| 统一 envelope | `api/envelope.py` + 异常处理器 | `tests/test_envelope.py` 遍历所有路由断言 |
| 每行代码带注释 | 业务代码逐行注释；生成物/第三方除外 | `scripts/check_line_comments.py`（覆盖率 ≥95%，白名单除外） |

> 逐行注释会降低密度可读性，因此约定：注释写"为什么/约束"，不写"把 a 赋给 b"；测试与脚本同样适用。

## 10. 阶段计划（每阶段固定四项交付）

### P0 Harness 骨架

- **① 变更文件**：`config.yaml`、`app/api/{envelope,errors,auth}.py`、`app/harness/{schema,runner,trace,guards}.py`、`app/model/{gateway,fake}.py`、`app/main.py`、`tests/test_{schema,envelope,guards}.py`、`scripts/verify_p0.py`、`scripts/check_{config,comment_rules,line_comments,imports}.py`、`docker-compose.yml`
- **② 启动与自测**：`docker compose up -d qdrant postgres` → `uv sync` → `uvicorn app.main:app --reload` → `pytest -q`
- **③ 验证脚本**：`python scripts/verify_p0.py` —— 用 FakeModel 跑 3 条用例，断言：envelope 三键齐全、schema 非法被拦、`E_NO_EVIDENCE` 触发、trace 文件生成且含 prompt 版本
- **④ 最可能出问题**：本地模型未就绪导致端到端跑不通 → 必须先用 FakeModel 把契约与闸门跑通，模型接入只作为可替换依赖

### P1 领域模型与多维知识库

- **① 文件**：`app/domain/{fact,indicator,rule,design,verdict}.py`、`app/knowledge/{ingest,chunk,index,retrieve}.py`、`scripts/ingest.py`、`scripts/verify_p1.py`、`tests/knowledge/*`
- **② 命令**：`python scripts/ingest.py --config config.yaml --source ../docs` → `python scripts/verify_p1.py`
- **③ 验证脚本**：断言 36 条事实全部入库且 `f` 编号唯一；对 5 个测试问题检索，命中正确 `fact_id` 且无越权角色结果
- **④ 最可能出问题**：按段落切分会把"f31 与 12 分钟"切断 → 必须按事实条目切分，并校验编号完整性

### P2 记忆层

- **① 文件**：`app/memory/{store,policy,profile}.py`、`app/memory/mem0_adapter.py`、`tests/memory/*`、`scripts/verify_p2.py`、`config.yaml`（memory 段）
- **② 命令**：`python scripts/verify_p2.py`
- **③ 验证脚本**：写 3 条记忆 → 注入冲突 → 断言不自动合并；按角色过滤后不可见内容召回数为 0；90 天 TTL 生效
- **④ 最可能出问题**：Mem0 升级改动 API 或索引结构 → 适配器隔离 + 锁版本 + 降级到 SQLite 检索

### P3 核心智能体与证据闸门

- **① 文件**：`app/agents/{a1_evidence,a2_conflict,a3_baseline,a5_verify}.py`、`app/harness/prompts/`（版本化）、`evals/cases/{evidence,conflict,no_evidence}.yaml`、`scripts/eval_run.py`、`scripts/verify_p3.py`
- **② 命令**：`python scripts/eval_run.py --suite evidence-v1` → `python scripts/verify_p3.py`
- **③ 验证脚本**：断言 FF1（带 fact_id 100%）、FF2（负例拒答 ≥95%）、FF3（schema 合法 100%）；任一不过返回非零退出码
- **④ 最可能出问题**：模型对"没有证据也要给结论"的倾向 → 闸门必须在生成后强制校验，而不是靠 prompt 约束

### P4 方案生成 + 编排 + 人工闸门

- **① 文件**：`app/agents/a4_design.py`、`app/orchestrator/{graph,state,checkpoint}.py`、`app/api/routes_{tasks,gate}.py`、`tests/orchestrator/*`、`scripts/verify_p4.py`
- **② 命令**：`uvicorn app.main:app` → `python scripts/verify_p4.py --scenario warehouse`
- **③ 验证脚本**：端到端建任务→七步跑通→断言无写操作、无自动审批、`needs_human` 项挂起；kill 进程后 `resume` 从 checkpoint 继续且不重复发提示
- **④ 最可能出问题**：状态机恢复时 trace/记忆重复写入 → 用 `task_id + step + input_hash` 做幂等键

### P5 评估、回放与灰度

- **① 文件**：`evals/cases/holdout/*`、`app/harness/{replay,fault_inject}.py`、`scripts/{replay_check,bench_p95,drill}.py`、`docs/runbook.md`、CI 配置
- **② 命令**：`python scripts/replay_check.py --trace var/trace/<id>.jsonl` → `python scripts/bench_p95.py` → `python scripts/drill.py --fault vector_down`
- **③ 验证脚本**：断言 FF6（回放结构一致 100%）、FF5（P95 ≤8s）、故障注入后降级路径生效且 `degraded=true`
- **④ 最可能出问题**：trace 体积膨胀（全量 prompt 落盘）→ 采样 + 压缩 + 只保留哈希与截断片段

## 11. 风险登记册

| 风险 | 概率 | 影响 | 缓解 | 责任 |
|---|---|---|---|---|
| 本地模型 JSON 不合法 | 高 | 流程中断 | 契约+修复重试+规则兜底；先用 FakeModel 打通 | 后端 |
| 事实幻觉（编造 f 编号） | 中 | 结论不可用 | 证据闸门强校验 + 编号存在性检查 | A5 / 闸门 |
| 中文专业术语召回差 | 中 | 检索不准 | 混合检索 + rerank + 术语表 profile | 知识库 |
| 单卡显存不足 | 中 | 无法跑 14B | 7B 降级 + 量化 + 模型路由 | 运维 |
| 越权召回 | 低 | 合规事故 | 角色过滤在检索层，不在 prompt 层 | 平台 |
| 评估集过拟合 | 中 | 指标虚高 | holdout 集 + 每阶段新增负例 | 评估 |
| 审批矩阵未定 | 高 | 上线阻断 | HumanGate 默认挂起，超时不通过 | 业务 |
