## 两套方案的关系

1. **业务方案**（`仓内拣选与装车核验-技术方案.md`）：解决"现场怎么拦错"。判定用确定性规则，提示只做解释，不阻断、不写业务库。
2. **系统方案**（`智能体系统-技术方案.md`）：解决"FDE 交付链怎么被智能体可靠地跑出来"。先建 harness（契约 / 执行 / 闸门 / trace / 评估），再挂 agent；模型可替换，判定仍在代码里。

两者共用同一条底线：**结论必须可回溯到事实编号（f00–f55），无证据即拒答**。

## 系统方案要点（摘要）

- 架构：模块化单体 + 多智能体流水线（拒绝微服务先行、拒绝云端模型）
- 推理：本地 OpenAI 兼容网关（Ollama / vLLM），Qwen2.5-14B 主 + 7B 降级
- 记忆：Mem0 自托管，四层（working / episodic / semantic / procedural），仅核验通过才写 semantic
- 知识库：四维（事实 / 规则 / 指标 / 案例）× 三轴（版本 / 角色 / 置信）
- 质量：五层 harness + 7 条可测适配函数（证据可追溯、负例拒答 ≥95%、schema 合法 100%、越权 0 次、P95 ≤8s、可回放 100%、依赖方向违规 0）
- 阶段：P0 harness → P1 知识库 → P2 记忆 → P3 核心 agent → P4 编排与人工闸门 → P5 评估/回放
