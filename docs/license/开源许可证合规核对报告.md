### 2.3 第三方组件

`cmake/util/makeself/` 为打包工具 makeself，随附 `COPYING` 为 GNU General Public License Version 2（1991 年 6 月）。该组件为独立构建工具，以目录形式内置，本次迁移完整保留其许可证文本，未做删改。

合规义务：分发时须保留 COPYING 全文，并提供该组件的对应源码（本仓库已随附源码）。GPL-2.0 义务仅及该组件本身，不等同于对整个算子工程施加 GPL。

### 2.4 主要风险

**高风险：缺许可证即无授权依据。** 仓库根目录没有 LICENSE，源码却明确标注 All rights reserved。按伯尔尼公约默认规则，无许可证意味着保留所有权利，他人复制、修改、分发均缺乏授权。当前该仓库与迁入目录都只能定位为"课程作业归档"，不能对外声明为可复用代码。

**风险来源判断。** 该工程代码结构与 CANN 官方算子样例高度一致，样例通常随 CANN 协议或 Apache-2.0 发布。若确属样例衍生，应在补齐原始许可证文本后方可对外提供；这一点必须向上游确认，不能由工程侧推定。

**中风险：个人身份信息。** `week3/` 下的 docx 与 README 含姓名、学号、班级、院校。公开仓库会暴露这些信息，需由本人决定是否保留。

## 三、对象二：第三周开源合规作业（pip 扫描）

该作业本身的结论可以复用，作为本仓库许可证治理的方法依据。

### 3.1 扫描设置

| 项目 | 内容 |
|---|---|
| 扫描对象 | pip 26.2.1 源码包，574 个文件、66 个目录、6.06 MB |
| 工具 | ScanCode Toolkit 32.5.0（Apache-2.0） |
| 命令 | `scancode -clpi --json-pp pip-scan.json --html pip-scan.html --timeout 180 pip-26.2.1` |
| 结果 | 错误 0；检出许可证文件 86 个（15.0%）；许可证匹配 148 处；版权声明 73 条（去重 32 条） |

### 3.2 关键发现

1. **主项目识别准确**：根目录 `LICENSE.txt`、`pyproject.toml`、`PKG-INFO` 均判为 MIT，置信度 100。
2. **文件级覆盖率低不等于无许可证**：488 个未检出文件中 `.py` 348 个、`.rst` 68 个、`.md` 42 个。pip 只在根目录集中声明 MIT，因此合规判断必须结合包级结论。
3. **多许可证共存**：18 个内置组件覆盖 MIT、Apache-2.0、BSD-2/3-Clause、ISC、MPL-2.0、Python-2.0 七类，与 `vendor.txt` 逐一对照后主要判定一致。
4. **需人工复核的两类偏差**：组合表达式（如 packaging 的 BSD-3-Clause OR Apache-2.0、tomli 的 MIT AND Python-2.0）与误报（`packaging/licenses/__init__.py` 被判为专有许可证，置信度 80）。
5. **兼容性结论**：pip 以 MIT 分发，内置组件以宽松许可证为主，可整体再分发，核心义务是"保留声明、标注修改"；MPL-2.0 仅对 certifi 形成文件级弱 copyleft。

### 3.3 可迁移到本仓库的四条做法

| 做法 | 在本仓库的落地 |
|---|---|
| 包级 + 文件级交叉判断 | 先看根目录 LICENSE（本仓库缺失），再看版权头与第三方目录 |
| 组合表达式必须人工复核 | makeself 的 GPL-2.0 与华为版权并存，需分别处理 |
| 低置信度结果不作法律结论 | 本报告只记录事实，不给"可以合法分发"的结论 |
| 接入 CI 并输出 SBOM | 建议在合并后的仓库增加许可证扫描与 THIRD-PARTY-NOTICES |

## 四、合并后仓库层面的结论

### 4.1 两条内容线必须分开标注

| 内容线 | 位置 | 许可证状态 |
|---|---|---|
| FDE 需求发现与智能体系统 | `docs/`、`fde-agent/` | 本项目原创内容，未附许可证 |
| CANN GELU 算子课程工程 | `integrated/cann-gelu/` | 上游无 LICENSE，华为版权 + GPL-2.0 第三方组件 |

两条线没有代码依赖，构建方式与验收标准完全不同。对外引用时必须分别标注来源，不能用一个许可证覆盖全部内容。

### 4.2 本仓库不授予再许可

`FDE-zuoye` 至今没有 LICENSE 文件。合并后仍应保持这一状态，直到明确权利归属：一旦添加宽松许可证，会被理解为对华为版权代码与课程作业一并授权，这超出了当前可确认的范围。
